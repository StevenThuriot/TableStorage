TableStorage

Azure Data Tables & Blobs, simplified.

A streamlined, source-generated .NET library built for performance, Native AOT compatibility, and developer ergonomics.

Get Started GitHub NuGet

Features

⚡

Source Generated

Zero-reflection context and model generation via Roslyn source generators. Fully Native AOT compatible.

🔗

LINQ Queries

Server-side filtering with Where, SelectFields, Take, ExistsIn, BatchDelete, and more.

📦

Blob Storage

Block and Append blob sets with custom serialization, tags, and full CRUD support.

🔀

Fluent Entities

Store multiple entity types in a single table with type-safe discriminators and pattern matching.

🚀

Bulk & Transactions

Bulk insert, update, upsert, delete — plus safe transactions with auto-chunking and partition grouping.

🔍

Change Tracking

Opt-in change tracking sends only modified properties back to the server, reducing bandwidth.

Quick Start

1

Install

Shell 
dotnet add package TableStorage.Core
dotnet add package TableStorage
2

Define your context and model

C# 
[TableContext]
public partial class MyTableContext
{
    public TableSet<Product> Products { get; set; }
}

[TableSet(PartitionKey = "Category", RowKey = "ProductId")]
public partial class Product
{
    public partial string Category { get; set; }
    public partial string ProductId { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}
3

Register and use

C# 
// Registration
builder.Services.AddMyTableContext(
    builder.Configuration.GetConnectionString("Storage"));

// Usage
public class ProductService(MyTableContext db)
{
    public Task<Product?> GetAsync(string category, string id, CancellationToken ct)
        => db.Products.GetEntityOrDefaultAsync(category, id, ct);

    public IAsyncEnumerable<Product> GetCheapAsync()
        => db.Products
              .Where(p => p.Price < 10m)
              .Take(50);
}

API at a Glance

Table Operations

C# 
// CRUD
await set.AddEntityAsync(entity);
await set.GetEntityOrDefaultAsync(pk, rk);
await set.UpdateEntityAsync(entity);
await set.UpsertEntityAsync(entity);
await set.DeleteEntityAsync(entity);

// Bulk
await set.BulkInsertAsync(entities);
await set.BulkUpdateAsync(entities);
await set.BulkUpsertAsync(entities);
await set.BulkDeleteAsync(entities);

// LINQ
var results = set
    .Where(x => x.Active)
    .SelectFields(x => new { x.Name })
    .Take(100);

await set.Where(x => !x.Active).BatchDeleteAsync();

Fluent Entities

C# 
// Store multiple types in one table
public TableSet<FluentTableEntity<Customer, Order>>
    MixedEntities { get; set; }

// Implicit conversion in & out
FluentTableEntity<Customer, Order> e = customer;
Customer back = e;

// Pattern matching
var result = entity.SwitchCase(
    case1: c => $"Customer: {c.Name}",
    case2: o => $"Order: {o.OrderNumber}"
);

// Safe fallback
var value = entity.SwitchCaseOrDefault(
    case1: c => Process(c),
    case2: o => Process(o),
    defaultCase: () => "Unknown"
);

// Inspect type
FluentBackingType type = entity.GetBackingType();
object? raw = entity.GetValueOrDefault();

RuntimeCompilations

C# 
// Enable runtime compilation
options.EnableCompilationAtRuntime();

// Update via expression — no entity needed
await table.Movies.UpdateAsync(() => new Movie
{
    PartitionKey = "sci-fi",
    RowKey = "matrix",
    Rating = 5
});

// Upsert via expression
await table.Movies.UpsertAsync(() => new Movie
{
    PartitionKey = "sci-fi",
    RowKey = "interstellar",
    Rating = 5
});

// Batch update with a transform expression
await table.Movies
    .Where(m => m.PartitionKey == "sci-fi")
    .BatchUpdateAsync(m => m with { Rating = 5 });

// Select projections
await foreach (var item in table.Movies
    .Where(m => m.Rating > 3)
    .Select(m => new { m.RowKey, m.Rating }))
{
    Console.WriteLine($"{item.RowKey}: {item.Rating}");
}

Fluent Entities

Store multiple entity types in a single Azure table with type-safe discriminators, implicit conversions, and pattern matching. Supports 2–16 type parameters across two packages.

Discriminator Strategies

C# 
// 1. $type column discriminator (default)
public TableSet<FluentTableEntity<Customer, Order>>
    ByType { get; set; }

// 2. PartitionKey discriminator
public TableSet<FluentPartitionTableEntity<Customer, Order>>
    ByPartition { get; set; }

// 3. RowKey discriminator
public TableSet<FluentRowTypeTableEntity<Customer, Order>>
    ByRowKey { get; set; }

// Up to 16 types with Fluent.Extended
public TableSet<FluentTableEntity<T1, T2, T3, T4, T5>>
    MultiType { get; set; }

Working with Fluent Entities

C# 
// Store — implicit conversion
var customer = new Customer { Name = "Jane" };
await context.MixedEntities.AddEntityAsync(customer);

// Retrieve
var entity = await context.MixedEntities
    .GetEntityOrDefaultAsync(pk, rk);

// Pattern match
var msg = entity.SwitchCase(
    case1: c => $"Customer: {c.Name}",
    case2: o => $"Order: {o.OrderNumber}"
);

// Iterate mixed table
await foreach (var e in context.MixedEntities)
{
    if (e.GetBackingType() == FluentBackingType.First)
    {
        Customer c = e; // implicit cast
    }
}

Use Cases

  • Store related but different entity types in one table for efficient partitioning
  • Unified query interface across multiple entity types
  • Event sourcing or activity streams with multiple event types
  • Polymorphic storage without separate tables

Runtime Compilations

By default, all LINQ query visitors are source-generated for full Native AOT support. The RuntimeCompilations packages add an alternative: expressions are compiled at runtime, enabling maximum query flexibility when AOT is not required.

Installation

Shell 
# Pick the package(s) matching your usage
dotnet add package TableStorage.RuntimeCompilations
dotnet add package TableStorage.Blobs.RuntimeCompilations
dotnet add package TableStorage.Fluent.RuntimeCompilations

Enable

C# 
builder.Services.AddMyTableContext(
    connectionString,
    configure: options =>
    {
        // Compile LINQ expressions at runtime
        // instead of using source-generated visitors
        options.EnableCompilationAtRuntime();
    }
);

Beyond enabling runtime compilation, these packages unlock expression-based APIs that let you update and project entities without materializing full objects.

Expression Updates & Upserts

C# 
// Update a single entity via expression tree.
// Only the specified properties are sent — no
// need to fetch the entity first.
await table.Movies.UpdateAsync(() => new Movie
{
    PartitionKey = "sci-fi",
    RowKey = "matrix",
    Rating = 5
});

// Upsert works the same way — insert or merge
await table.Movies.UpsertAsync(() => new Movie
{
    PartitionKey = "sci-fi",
    RowKey = "interstellar",
    Rating = 5,
    Title = "Interstellar"
});

Batch Update with Transform

C# 
// Update all matching entities in bulk
// using a transform expression
int updated = await table.Movies
    .Where(m => m.PartitionKey == "sci-fi")
    .BatchUpdateAsync(m => m with { Rating = 5 });

// Same, but wrapped in transactions
int updated = await table.Movies
    .Where(m => m.PartitionKey == "sci-fi")
    .BatchUpdateTransactionAsync(
        m => m with { Rating = 5 });

// Also available directly on a TableSet
// (updates all entities in the table)
int updated = await table.Movies
    .BatchUpdateAsync(m => m with { Rating = 0 });

Select Projections

C# 
// Project to anonymous types or DTOs
await foreach (var item in table.Movies
    .Where(m => m.Rating > 3)
    .Select(m => new { m.RowKey, m.Rating }))
{
    Console.WriteLine($"{item.RowKey}: {item.Rating}");
}

// Select with Take
await foreach (var item in table.Movies
    .Where(m => m.PartitionKey == "sci-fi")
    .Take(10)
    .Select(m => new { m.Title, m.Rating }))
{
    // ...
}

// Select directly on a TableSet
await foreach (var item in table.Movies
    .Select(m => new MovieSummary(m.Title, m.Rating)))
{
    // ...
}

Method Reference

Method Available on Description
UpdateAsync(Expression)TableSetMerge-update a single entity via expression
UpsertAsync(Expression)TableSetInsert-or-merge via expression
BatchUpdateAsync(Expression)TableSet, Where, query chainsBulk update all matching entities
BatchUpdateTransactionAsync(Expression)TableSet, Where, query chainsSame as above, wrapped in transactions
Select(Expression)TableSet, Where, TakeProject entities to a different shape

When to use: Choose RuntimeCompilations when you need expression-based Updates, Upserts, Select projections, or dynamic queries. Stick with the default source-generated visitors for AOT-compatible, trimmer-safe builds where these APIs are not needed.
